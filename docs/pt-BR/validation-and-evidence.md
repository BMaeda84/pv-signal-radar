# Estratégia de validação e matriz de evidências

Este é um registro de evidências de engenharia baseado em risco, não uma alegação de validação regulatória, qualificação GxP, validação clínica nem adequação a todo protocolo de pesquisa. “Verificado localmente” significa que a checagem indicada passou na sessão de evidências de desenvolvimento em 2026-09-02. Isso não significa que o CI do GitHub executou, que um artefato de release foi atestado ou que o controle foi exercitado em um trimestre oficial do FAERS.

## Evidências de aceitação exigidas para release de dataset

1. commit Git exato, `renv.lock` revisado, seu checksum, evidência de restore/status limpo e inventário de hashes dos archives de pacotes;
2. registro de fontes com hashes verificados, URLs oficiais, cobertura exata e disposição de licença da fonte;
3. checagens bem-sucedidas de fixture, schema, QA, invariantes, budget de archive, budget de join e reexecução;
4. reconciliação das contagens brutas/atuais/elegíveis e explicação dos desvios em um trimestre oficial;
5. comparação semântica de dois builds limpos, checksums dos artefatos, digest canônico do resultado/família e explicação de onde identidade de bytes Parquet não é esperada;
6. benchmark numérico independente e relatório de reference set para todo threshold ou método habilitado;
7. revisão científica independente, revisão de privacidade/licença, aprovador de release nomeado e aceitação dos riscos residuais;
8. controles remotos protegidos de publicação e uma execução de release que produza evidências retidas de SBOM/proveniência; e
9. localização imutável dos artefatos, DOI ou ID persistente, procedimento de rollback/retirada e rota de correção.

## Escopo não verificado

Throughput e memória em trimestre real, variantes antigas de schema/codificação FAERS, estabilidade de bytes entre versões do Arrow, atribuição e redistribuição de release MedDRA, normalização de ingrediente/conceito, atribuição de categoria clínica, saídas estratificadas/temporais, BCPNN, GPS/EBGM, valores Fisher batch acima do limite de recálculo online, completude cientificamente esperada da família de resultados e reexecução atestada de forma independente, reference sets positivos/negativos, ETL VigiMed, publicação compatível com S3, distribuição OCI do ambiente R, automação de DOI, controles de abuso com múltiplas réplicas e recuperação de falha do artifact store não foram validados pelas evidências atuais.
