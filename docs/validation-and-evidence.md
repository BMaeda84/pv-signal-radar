# Validation strategy and evidence matrix

This is a risk-based engineering evidence record, not a claim of regulatory validation, GxP qualification, clinical validation, or fitness for every research protocol. “Verified locally” means that the named check passed in the development evidence session on 2026-09-02. It does not mean that GitHub CI ran, that a release artifact was attested, or that the control was exercised on an official FAERS quarter.

## Required acceptance evidence for a dataset release

1. exact Git commit, reviewed `renv.lock`, its checksum, clean restore/status evidence, and a package-archive hash inventory;
2. source register with verified hashes, official URLs, exact coverage, and source licensing disposition;
3. successful fixture, schema, QA, invariant, archive-budget, join-budget, and repeat-run checks;
4. reconciliation of raw/current/eligible counts and explanation of deviations on an official quarter;
5. semantic comparison of two clean builds, artifact checksums, a canonical result/family digest, and an explanation where Parquet byte identity is not expected;
6. independent numerical benchmark and reference-set report for every enabled research threshold or method;
7. independent scientific review, privacy/license review, named release approver, and residual-risk acceptance;
8. protected remote publication controls and a release run that produces retained SBOM/provenance evidence; and
9. immutable artifact location, DOI or persistent ID, rollback/withdrawal procedure, and correction route.

## Unverified scope

Real-quarter throughput and memory, old FAERS schema variants/encodings, cross-version Arrow byte stability, MedDRA release assignment and redistribution, ingredient/concept normalization, clinical category assignment, stratified/timeline outputs, BCPNN, GPS/EBGM, batch Fisher values above the online recomputation bound, scientifically expected result-family completeness and independently attested reexecution, positive/negative reference sets, VigiMed ETL, S3-compatible publication, OCI distribution of the R environment, DOI automation, multi-replica abuse controls, and recovery from artifact-store failure have not been validated by the current evidence.
