# Estrategia de validación y matriz de evidencias

Este es un registro de evidencias de ingeniería basado en riesgos, no una afirmación de validación regulatoria, cualificación GxP, validación clínica ni aptitud para todo protocolo de investigación. “Verificado localmente” significa que la comprobación indicada se superó en la sesión de evidencias de desarrollo del 2026-09-02. No significa que el CI de GitHub se haya ejecutado, que un artefacto de release haya sido atestado ni que el control se haya ejercitado con un trimestre oficial de FAERS.

## Evidencias de aceptación requeridas para una release de dataset

1. commit Git exacto, `renv.lock` revisado, su checksum, evidencia de restore/status limpio e inventario de hashes de archives de paquetes;
2. registro de fuentes con hashes verificados, URLs oficiales, cobertura exacta y disposición de licencia de la fuente;
3. comprobaciones satisfactorias de fixture, schema, QA, invariantes, budget de archive, budget de join y repetición de ejecución;
4. reconciliación de los recuentos brutos/actuales/elegibles y explicación de desviaciones en un trimestre oficial;
5. comparación semántica de dos builds limpios, checksums de artefactos, digest canónico del resultado/familia y explicación de dónde no se espera identidad de bytes Parquet;
6. benchmark numérico independiente e informe de reference set para cada threshold o método habilitado;
7. revisión científica independiente, revisión de privacidad/licencia, aprobador de release designado y aceptación de riesgos residuales;
8. controles remotos protegidos de publicación y una ejecución de release que produzca evidencias retenidas de SBOM/procedencia; y
9. ubicación inmutable de artefactos, DOI o ID persistente, procedimiento de rollback/retirada y ruta de corrección.

## Alcance no verificado

Throughput y memoria en trimestre real, variantes antiguas de schema/codificación FAERS, estabilidad de bytes entre versiones de Arrow, asignación y redistribución de release MedDRA, normalización de ingrediente/concepto, asignación de categoría clínica, salidas estratificadas/temporales, BCPNN, GPS/EBGM, valores Fisher batch por encima del límite de recálculo online, completitud científicamente esperada de la familia de resultados y reejecución atestada de forma independiente, reference sets positivos/negativos, ETL de VigiMed, publicación compatible con S3, distribución OCI del entorno R, automatización de DOI, controles de abuso con múltiples réplicas y recuperación ante fallos del artifact store no han sido validados por las evidencias actuales.
